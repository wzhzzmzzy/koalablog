# Keep installation writes out of HTTP reads

Template Catalog initialization and legacy first-User migration run only during onboarding or an explicit existing-installation maintenance command, never in HTTP middleware. The earlier implementation plan's once-per-isolate initialization still charged every fresh Worker read with a Catalog UPSERT and a user-count query, including ordinary API reads. Moving these operations out of request handling makes cold and warm read paths equally read-only without changing the Catalog, User, or File revision contracts. Operators upgrading legacy sites must complete the explicit initialization before serving the new release; we accept that deployment step rather than retaining lazy read-triggered writes. This follows ADR-0006's rejection of read-triggered backfills and preserves ADR-0011's Session/API Token distinction and ADR-0012's Owner-only access rules.
